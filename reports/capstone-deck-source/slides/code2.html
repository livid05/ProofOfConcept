Queue: never lose a release

if (edge && armed) {

    next = (head + 1) & 15;

    if (next == tail) {

        key_queue_overflow++;

        head = tail = 0;

        sync_pending = 1;

    } else {

        queue[head] = stable_pressed

            ? KEY_HID_USAGE : 0;

        head = next;

    }

}

What it does

  • A press stores HID usage 0x04 (the A key); a release stores 0.
  • The 16-slot ring holds 15 events while USB is busy.
  • If it ever fills, firmware resets and sends all-keys-up, so no key sticks.
  • The tail advances only after the USB report is accepted.

Source: key_switch.c (one-key version; key_matrix.c queues whole reports the same way)
